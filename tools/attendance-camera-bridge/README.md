# پل محلی دوربین حضور و غیاب هیرمند

این ابزار برای اتصال XVR داهوا به بخش «حضور و غیاب» سایت است. تصویر RTSP و الگوهای تشخیص هویت روی رایانهٔ داخل دفتر پردازش می‌شوند؛ سایت فقط شناسهٔ کارمند، ورود/خروج، زمان، شناسهٔ دوربین و امتیاز تطبیق را دریافت می‌کند. هیچ تصویر یا بردار چهره‌ای به سایت ارسال نمی‌شود.

## امنیت و رضایت

- قبل از ثبت الگوی چهره، کارکنان را از هدف، شیوهٔ پردازش، مدت نگهداری، امکان اصلاح خطا و راه ارتباطی مطلع کن و رضایت/مبنای قانونی معتبر را ثبت کن. برای مراجعه‌کننده‌ها یا افراد خارج از کارکنان الگو نساز.
- از یک رایانهٔ ثابت داخل شبکهٔ دفتر استفاده کن؛ پورت RTSP دستگاه را در اینترنت منتشر نکن. برای XVR یک حساب فقط‌خواندنی بساز.
- یک رمز مستقل و تصادفی حداقل ۳۲ کاراکتری بساز. این رمز را در GitHub، فایل تنظیمات یا پیام عمومی قرار نده.
- فایل الگوها با Fernet رمز می‌شود؛ کلید رمزگذاری جداگانه روی همان رایانه ذخیره می‌شود. دسترسی Windows را به حساب کاربری اختصاصی محدود کن و از پوشهٔ داده نسخهٔ پشتیبان امن بگیر. رمزگذاری فایل جایگزین حفاظت از حساب و دیسک نیست.
- قبل از استفادهٔ واقعی، ورود و خروج کارکنان را در چند نوبت آزمایشی بررسی کن. تشخیص چهره ممکن است اشتباه کند؛ موارد «نیازمند بررسی» را قبل از استفاده در محاسبهٔ حقوق/ارزیابی عملکرد، دستی بازبینی کن.

## ۱. تنظیم سایت روی Liara

در متغیرهای محیطی برنامه این مقادیر را تعریف کن:

- `ATTENDANCE_CAMERA_SHARED_SECRET`: همان رمز تصادفی، حداقل ۳۲ کاراکتر.
- `ATTENDANCE_CAMERA_MIN_MATCH_SCORE`: ابتدا `0.48`؛ این امتیاز شباهت مدل است، **احتمال آماری یا تضمین هویت نیست** و باید در محیط واقعی کالیبره شود.

پس از ذخیرهٔ متغیرها، استقرار برنامه را انجام بده تا migration شمارهٔ `0100_staff_attendance_camera_bridge.sql` اجرا شود. کلید فقط باید در سمت سرور و روی رایانهٔ پل محلی باشد.

## ۲. نصب روی رایانهٔ دفتر

از Python 3.10 یا 3.11 و یک حساب Windows اختصاصی استفاده کن. از پوشهٔ `tools/attendance-camera-bridge` اجرا کن:

1. محیط مجازی بساز: `py -3.11 -m venv .venv`
2. آن را فعال کن: `.venv\\Scripts\\Activate.ps1`
3. وابستگی‌ها را نصب کن: `python -m pip install --upgrade pip` و سپس `pip install -r requirements.txt`
4. نمونهٔ تنظیمات را کپی کن: `Copy-Item config.example.json config.json`

نصب `insightface` ممکن است روی بعضی نسخه‌های ویندوز به ابزار ساخت C/C++ نیاز داشته باشد. مدل `buffalo_l` در اولین اجرا در حافظهٔ محلی مدل‌ها قرار می‌گیرد؛ فریم دوربین برای دانلود یا شناسایی به سرویس ابری فرستاده نمی‌شود.

## ۳. تعریف متغیرهای محلی

در PowerShell برای نشست فعلی:

```powershell
$env:HIRMAND_ATTENDANCE_CAMERA_SECRET = "<همان-رمز-تصادفی-تنظیم‌شده-در-Liara>"
$env:HIRMAND_XVR_CH1_RTSP = "rtsp://<کاربر>:<رمز>@<IP-محلی-XVR>:554/cam/realmonitor?channel=1&subtype=1"
$env:HIRMAND_XVR_CH2_RTSP = "rtsp://<کاربر>:<رمز>@<IP-محلی-XVR>:554/cam/realmonitor?channel=2&subtype=1"
```

`subtype=1` معمولاً زیرجریان کم‌حجم‌تر است؛ اگر وضوح برای تشخیص چهره کافی نبود، در مرحلهٔ آزمون جریان اصلی (`subtype=0`) را امتحان کن. رمز داخل URL باید در صورت داشتن نویسه‌های ویژه URL-encode شود. نشانی‌ها فقط باید به IP داخلی XVR اشاره کنند.

متغیرهای نشست فعلی پس از بستن ترمینال پاک می‌شوند. برای اجرای دائم، آن‌ها را در تنظیمات امن حساب Windows یا Task Scheduler قرار بده، نه در فایل‌های پیگیری‌شدهٔ Git.

## ۴. فهرست و ثبت کارکنان

فهرست کارکنان فعال از API امضاشده دریافت می‌شود:

```powershell
python enroll.py --list-staff --config config.json
```

برای هر کارمند فقط با اطلاع و رضایت او، حداقل سه تصویر واضح و روبه‌رو را از مسیر محلی انتخاب کن و شناسهٔ دقیق را از خروجی بالا استفاده کن:

```powershell
python enroll.py --employee-id "<شناسه-کارمند>" --name "<نام-کارمند>" --images "C:\\attendance-enrolment\\photo1.jpg" "C:\\attendance-enrolment\\photo2.jpg" "C:\\attendance-enrolment\\photo3.jpg" --config config.json
```

ابزار فقط الگوی عددی را در مخزن رمزگذاری‌شدهٔ محلی ذخیره می‌کند و تصویرهای ورودی را کپی نمی‌کند. تصاویر اصلی را طبق سیاست نگهداری امن نگه دار یا پس از تأیید ثبت الگو حذف کن.

## ۵. کالیبره‌کردن خط عبور

در `config.json` برای هر دوربین:
- `line` یک خط مجازی در مختصات نسبی تصویر است؛ مقدارها بین صفر و یک هستند.
- `entry_when` باید بر اساس جهت واقعی حرکت در همان تصویر انتخاب شود: `negative_to_positive` یا `positive_to_negative@.
- ابتدا هر دو دوربین با `enabled: false` می‌مانند. برای دیدن خط روی فریم محلی اجرا کن: `python preview.py --camera-id entrance_cam_1`. فایل تصویر فقط روی رایانه ذخیره می‌شود؛ آن را پس از کالیبراسیون حذف کن.
- خطوط را با نمای زندهٔ XVR تنظیم کن، سپس فقط یک دوربین را فعال و ورود و خروج آزمایشی را بررسی کن. بعد دوربین دوم را فعال کن. زاویهٔ دو دوربین ممکن است جهت متفاوتی در تصویر ایجاد کند.

پس از تنظیم و آزمون، `enabled` را برای دوربین کالیبره‌شده روی `true` قرار بده. تنظیم نمونه عمداً دوربین‌ها را خاموش نگه می‌دارد. پل از عبور خط و تطبیق پایدار چند فریم استفاده می‌کند؛ اگر شخص قبل از دیده‌شدن از خط عبور کرده باشد یا صورت پوشیده باشد، رویداد ممکن است ایجاد نشود.

## ۶. اجرای آزمایشی و دائمی

```powershell
python agent.py
```

در اولین اجرا پیام اتصال هر RTSP و خطاهای پیکربندی را در همان ترمینال می‌بینی. برای آزمایش، یک نفر در هر بار از در عبور کند و صفحهٔ «حضور و غیاب» را تازه‌سازی کن. صف محلی SQLite رویدادها را هنگام قطعی سایت نگه می‌دارد و بعداً با امضای تازه می‌فرستد. زمان‌های بیشتر از ۱۴ روز پذیرفته نمی‌شوند.

رویداد ورود یک نوبت با خروج خالی می‌سازد؛ تا وقتی خروج متناظر نرسد، جلسه «در حال حضور» است. خروج بی‌ورود، تکرار دو دوربین، تطبیق کم‌امتیاز یا نوبت قبلی باز به‌جای تغییر خودکار ساعات، در بخش رویدادهای دوربین با وضعیت «نیازمند بررسی» نمایش داده می‌شود.

## محدودیت‌های شناخته‌شده

- این یک تطبیق چهرهٔ محلی است، نه قابلیت شناسایی هویت در خود XVR؛ SMD Plus دستگاه صرفاً انسان/خودرو را از حرکت تفکیک می‌کند.
- آستانه و خط عبور به زاویه، نور، کیفیت دوربین و کارکنان واقعی وابسته است. هیچ امتیاز شباهتی به‌تنهایی تضمین هویت نیست.
- ساعات عبور از نیمه‌شب یا رویدادهایی که ترتیب ورود/خروجشان مبهم است برای اصلاح دستی کنار گذاشته می‌شوند.
- پیش از اجرای تمام‌وقت، نسخهٔ پشتیبان از PostgreSQL و پوشهٔ رمزگذاری‌شدهٔ محلی تهیه و سیاست نگهداری سوابق را مشخص کن.
